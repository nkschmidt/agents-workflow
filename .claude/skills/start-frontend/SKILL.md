# start-frontend — Запуск фронта и проброс через ngrok

## Когда применять

- Пользователь просит запустить фронт. **Не запускать автоматически.**

## Аргументы

`ARGUMENTS` — опционально путь к директории фронтенда и/или `--host <hostname>` для подмены Host заголовка.

## Процедура

### Шаг 1 — определить параметры

Из `ARGUMENTS` и контекста определить:
- **frontend_dir**:
  - если пользователь указал путь — использовать его;
  - иначе авто-детект: найти каталог с frontend `package.json` (содержит `dev`-скрипт) среди рабочих областей проекта (`submodules/*`, зоны монорепо — см. `PROJECT.md`) и типовых каталогов `./frontend`, `./client`, `./web`, `./app`, `.`;
  - если кандидатов несколько или ни одного — спросить пользователя, какую директорию запускать.
- **host_header**: если пользователь указал хост (`--host X`, «с хостом X», «host header X») — извлечь значение.

### Шаг 2 — запустить скрипт

Одна команда (пути определяются динамически через `git rev-parse`):

```bash
ROOT=$(git rev-parse --show-toplevel) && bash "$ROOT/.claude/skills/start-frontend/start.sh" "$ROOT" "$ROOT/<FRONTEND_DIR>" [HOST_HEADER]
```

- `ROOT` — корень проекта, определяется автоматически
- `<FRONTEND_DIR>` — относительный путь к директории фронтенда (например `submodules/backoffice`)
- `HOST_HEADER` — опционально, значение хоста для подмены

**ВАЖНО:** запускать с `dangerouslyDisableSandbox: true` — скрипт запускает фоновые процессы. PID-файлы и логи кладутся в `.tmp/` (gitignore).

### Шаг 3 — обработать результат

Скрипт возвращает JSON на stdout:
- **Успех:** `{"status":"ok","url":"...","port":5173,"frontend_pid":123,"ngrok_pid":456,"host":"..."}`
- **Ошибка:** `{"status":"error","message":"..."}` на stderr

При успехе — сообщить пользователю:

```
🚀 Фронт запущен!
🔗 <url>
📁 <frontend_dir>
⚡ порт <port>
🏷 Host: <host>   ← только если указан

Скажи "стоп фронт" чтобы остановить
```

При ошибке — показать сообщение об ошибке.

## Запрещено

- Запуск без явной команды пользователя.
- Коммит или изменение файлов проекта.
